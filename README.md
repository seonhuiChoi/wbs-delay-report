# 지연원인 분석 리포트 — 데모 + 산출물 양식 + 설계문서

> **📊 리포트 바로 보기 → https://seonhuichoi.github.io/wbs-delay-report/**
>
> 저장소를 클론하지 않아도 위 링크에서 한 페이지 리포트를 그대로 볼 수 있다.
> 양식(`templates/`)과 설계문서(`design/`)는 저장소에서 내려받는다.

출발점은 WBS 엑셀을 파싱해 진척률·지연 건수를 요약하는 일일 리포트였다.
그런데 그건 **기존 일정관리 프로그램으로도 그대로 뽑을 수 있는 정보**였다.
이 버전은 회의록 · 액션아이템 · 설계산출물 · 이슈 · 변경요청을 **WBS_ID로 조인**해,
지연 TASK마다 **왜 늦었는지(원인)** 와 **무엇을 하면 회복되는지(처방)** 까지 도출한다.

### 핵심 과업 — AI 스케줄 자동편성 (제약 기반)

**이 엔진은 학습하지 않는다.** 과거 근태 실적으로 수요를 예측하지 않는다.
근무유형 표준과 근태 신청을 받아 **법정 제약을 만족하면서 공평하게 배정하는 계산**을 한다.

```
입력   근무유형 표준 14종                      (DS-014)
      점포·부문·시간대별 필요인원 기준           ← 현업이 정하는 기준정보, 예측 아님
      개인 근태신청 (연차·반차·경조·교육·희망근무)
      개인 속성 (계약 소정시간·자격·법정 제한)
      공정성 이력 (개인별 누적 야간·휴일 배정)
        ↓
엔진   CP-SAT 제약 최적화
      Hard 12종  법정 근로시간 · 계약 · 자격 · 승인된 부재 · 최소 배치
      Soft  6종  형평성 0.30(최상위) · 충족률 0.25 · 희망반영 0.18 · …
        ↓
출력   배정안 + 배정 근거 3종 + 형평성 지표(지니계수)
```

**왜 학습 방식을 쓰지 않는가**

1. 배정은 정답이 하나인 문제가 아니라 **제약을 만족하는 해를 찾는 문제**다.
2. 법정 근로시간 위반은 "대체로 안 어긴다"로 부족하다. **결정론적으로 0건**이어야 한다.
3. 과거 실적을 학습하면 **과거의 불공정한 배정 관행까지 학습**한다. 야간이 특정 인원에게 몰려 있었다면 모델은 그걸 정답으로 배운다.
4. 개인 근태 이력의 학습 목적 반출이 불필요해져 **도입 장벽이 낮아진다.**

### 이 프로젝트의 진짜 마감일

계약 종료일(12-31)이 아니라 **연말 성수기 IT 변경 동결 시작일(12-14)** 이다.

```
계획 오픈       2026-12-04 (금)
변경 동결       2026-12-14 (월) ~ 2027-01-08 (금)
무조치 시       오픈 준비 완료 12-22 → 동결 진입 → 실제 오픈 2027-01-11 (+38일)
조치 적용 시    오픈 2026-12-09 (수) → 동결 2영업일 전 안착
```

## 핵심 구조

### 1. 조인 키는 `WBS_ID` 하나

모든 문서가 `WBS_ID`를 필수 컬럼으로 갖는다. 지연 TASK 하나를 잡으면
그 TASK에 걸린 회의록 미결·액션아이템·산출물 검토상태·이슈·CR을 한 번에 끌어온다.

### 2. 원인은 10개 코드로 분류 (`RC-01` ~ `RC-10`)

요건변경 · 의사결정 지연 · 선행공정 지연 · 산출물 미승인 · 액션아이템 미이행 ·
자원 과부하 · 외부 의존성 · 품질 재작업 · **기술 난이도(검증 미달)** · **기준정보·환경 미비**

### 3. 원인 판정은 10개 규칙이 자동 수행 (`R-01` ~ `R-10`)

예) `R-02` : `MAX(기준일 − 미결.결정필요일) ≥ 5 AND TASK.CP여부 = 'Y'` → `RC-02` (가중치 0.95)

점수 최고값이 주원인, 0.5 이상이 부원인. **Pareto 집계는 주원인 기준으로만** 해서 지연일수 이중계상을 막는다.
`RC-03`(연쇄)이 주원인이면 선행 TASK를 재귀 탐색해 **근본 원인까지** 표기한다.

### 4. 입력 무결성은 10개 점검이 감시 (`V-01` ~ `V-10`)

가장 중요한 것은 `V-08` **CR 재기준선 미반영**. 승인된 변경요청의 공수가 WBS에 반영되지 않으면
계획선이 옛 기준으로 남아 **SPI가 실제보다 나쁘게** 나온다.

## 이 데모가 보여주려는 것

지연 46일 중 **26일(56.5%)이 AI 과업**에서 발생했다. 그런데 근거를 따라가면 원인은 AI 기술이 아니다.

```
CASE 1  4.3.2 근무유형 표준 (RC-02)     노사 합의 3회 이월 · 20일
           └─▶ 결정 변수 정의역 미확정 → CP-SAT 탐색공간 3.2배
                  └─▶ CASE 4  최적화 412초 (목표 180초)
           └─▶ CASE 3  5.4.1 최적화 엔진 착수 불가 (RC-03)

CASE 2  4.6.1 편성 기준정보 (RC-10)      필요인원 기준 44/71개점 · 13일
           └─▶ 27개점 임시값 사용
                  └─▶ CASE 4  충족률 91.2% (목표 95%)
           └─▶ 희망 신청 채널 미개설
                  └─▶ CASE 4  희망 반영 58% (목표 70%)
```

1차 시뮬레이션 5개 지표 중 4개가 미달했지만 **법정 제약 위반은 0건** — 엔진 골격은 정상 동작한다.
미달 4개 중 **3개는 입력 조건**, 1개(형평성 지니 0.31)만 엔진 고유 문제였고,
그 원인도 명확했다 — **노측이 가장 중요하게 본 항목을 소프트 제약으로 두었기 때문**이다.

그래서 처방은 "알고리즘 교체"가 아니라 **"입력 조건 2건 확정 + 형평성 상한을 하드 제약으로 승격"** 이 된다.
알고리즘을 바꿨다면 진짜 원인 3건은 그대로 둔 채 2~3주를 더 썼을 것이다.

또 하나 — **CASE 2의 대응은 독촉이 아니다.** 미회신 27개점 중 16개점은
"기준이라 할 만한 것이 원래 없었다". 그동안 점포장 경험으로 편성해왔기 때문이다.
회신을 안 해준 게 아니라 **회신할 내용이 없었다.** 그래서 처방이 *본사가 초안을 만들어 가는 워크숍*이 된다.

**WBS만 봤다면 "AI 설계가 늦다"까지밖에 못 본다.** 회의록·이슈·산출물을 조인해야 이 결론이 나온다.

## 도입 시 실제로 바꿔야 하는 것 — 4가지

1. 회의록 양식에 **연관 WBS_ID** 칸을 추가한다.
2. 미결사항에 **결정필요일 · 결정권자**를 적는다.
3. 액션아이템에 **연관 WBS_ID**를 적는다.
4. 지연 TASK에 **RC 코드**를 고른다 (10개 중 택 1).

이슈대장 · CR대장 · 산출물목록은 대부분의 SI 프로젝트가 이미 관리하는 문서다.
새 도구 도입이 아니라 **이미 쓰는 문서에 조인 키를 넣는 것**이 전부다.

## 보는 방법

`index.html`을 브라우저로 열면 된다. 외부 리소스는 Google Fonts뿐이고 나머지는 자체 포함이다.
섹션 03의 케이스 카드는 클릭해서 접고 펼 수 있다. 인쇄(Ctrl+P) 시 카드가 모두 펼쳐진 상태로 출력된다.

리포트의 문서ID(`DS-014` `MT-2026-031` `AI-078` 등)는 `templates/` 대장과 `design/` 설계문서에서
같은 ID로 조회된다. **리포트의 주장과 산출물의 내용이 같은 데이터를 가리키는지** 확인해 볼 수 있다.
