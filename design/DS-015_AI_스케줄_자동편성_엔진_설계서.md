## 1. 개요

### 1.1 이 엔진이 하는 일 — 그리고 하지 않는 일

이 엔진은 **규칙과 제약으로 계산**한다. 과거 데이터를 학습하지 않는다.

| | 방식 |
|---|---|
| **한다** | 법정·계약·자격 제약을 만족하는 배정안을 **탐색**한다 |
| **한다** | 야간·휴일이 특정 인원에 몰리지 않도록 **공평하게 분배**한다 |
| **한다** | 개인의 연차·교육·희망근무 신청을 **반영**한다 |
| **하지 않는다** | 과거 근태 실적을 학습해 미래 수요를 **예측하지 않는다** |
| **하지 않는다** | 통계 모델로 필요 인원을 **추정하지 않는다** |

필요 인원은 **현업이 정한 기준정보**(`DS-016`)에서 조회한다. 예측 대상이 아니라 입력값이다.
"토요일 14–16시 계산 부문 6명"은 모델이 맞히는 값이 아니라 점포운영팀이 정하는 값이다.

> **왜 학습 방식을 쓰지 않는가**
> ① 근태 배정은 정답이 하나로 정해지는 문제가 아니라 **제약을 만족하는 해를 찾는 문제**다.
> ② 법정 근로시간 위반은 확률적으로 "대체로 안 어긴다"로는 부족하다. **결정론적으로 0건**이어야 한다.
> ③ 과거 실적을 학습하면 **과거의 불공정한 배정 관행까지 학습**한다. 야간이 특정 인원에 몰려 있었다면 모델은 그것을 정답으로 배운다.
> ④ 개인정보(근태 이력) 학습 목적 반출이 불필요해져 도입 장벽이 낮아진다.

### 1.2 목적

71개 점포 8,400명의 근무 스케줄을 자동 편성해, **점포장이 매주 4~6시간 쓰던 편성 작업을 30분 검토로** 줄인다.
자동 편성의 결과는 *제안*이며, 점포장 승인 없이 확정되지 않는다.

### 1.3 적용 범위

| 구분 | 범위 |
|---|---|
| 대상 점포 | 대형마트 62개점 · 백화점 9개점 (트레이더스 포함) |
| 대상 인원 | 직영 8,400명 (협력·판촉 3,100명은 범위 외 — CR-2026-008 반려) |
| 편성 단위 | 점포 × 부문 × 30분 슬롯 |
| 편성 주기 | 4주 단위 사전 편성, 주 1회 롤링 재편성 |
| 확정 시점 | 근무 개시 2주 전 |

### 1.4 설계 원칙

1. **법정 제약은 소프트 제약이 될 수 없다.** §4.2 위반 해는 실행 가능해에서 제외한다.
2. **공정성은 결과가 아니라 제약이다.** 사후 지표가 아니라 목적함수의 최상위 항목으로 넣는다.
3. **모든 배정은 설명 가능해야 한다.** 근거를 제시하지 못하는 배정은 현장에서 수용되지 않는다. (§6)
4. **실패 시 안전하게 멈춘다.** 해를 찾지 못하면 부분해를 내지 않고 위반 제약을 지목한다. (§8.3)

## 3. 소요 확정 (①) — 예측이 아닌 조회

### 3.1 필요 인원 산정

```
req[s][d][k] = 기준정보.필요인원( 점포 s, 부문 d, 슬롯 k, 요일유형, 영업유형 )
```

| 축 | 값 |
|---|---|
| 요일유형 | 평일 / 토 / 일 / 공휴일 / 의무휴업일 |
| 영업유형 | 정상 / 연장영업 / 행사기간 / 명절 특별운영 |
| 슬롯 | 영업시간 내 30분 단위 |

기준정보는 `DS-016` §3에 정의된 **점포운영팀 확정 테이블**이며, 엔진은 이를 그대로 읽는다.
행사·명절처럼 인원이 늘어나는 구간은 **기준정보에 별도 행으로 사전 등록**한다.

### 3.2 기준정보가 없을 때

| 상황 | 처리 |
|---|---|
| 해당 슬롯 기준 미등록 | 동일 점포·동일 부문의 **같은 요일유형 기준**을 사용 |
| 점포 전체 기준 미등록 | 동일 점포유형·유사 규모 점포의 기준을 **임시 적용**하고 화면에 <b>임시값</b> 배지 표시 |
| 임시값 사용 비율 | 편성 결과에 함께 표기 — 점포장이 신뢰도를 판단할 수 있게 |

> 2026-10-08 기준 71개점 중 **44개점(62%)만 기준정보 확정**. 나머지 27개점은 임시 적용 상태이며,
> 이것이 §9 1차 시뮬레이션에서 충족률 91.2%(목표 95%)로 나타난 직접 원인이다. (`DS-016` §5, ISS-018)

## 4. 배정 최적화 (③)

### 4.1 결정 변수

```
x[e][t][w] ∈ {0,1}   사원 e 가 날짜 t 에 근무유형 w 로 배정되면 1
                      e ∈ 점포 소속 사원, t ∈ 편성기간 28일,
                      w ∈ 근무유형 14종 ∪ {WT-00 휴무}

파생값
  h[e][t]      소정근로시간   (근무유형 w 의 정의값 — DS-014)
  n[e][t]      야간근로시간
  ot[e][t]     연장근로시간
  cov[s][d][k] 슬롯 배치 인원 수
```

**정의역 크기** — 근무유형이 표준 14종이면 사원당 `28 × 15 = 420`개 변수.
현행 47종을 그대로 쓰면 `28 × 48 = 1,344`개로 **약 3.2배**가 된다. (§9.3 참조)

### 4.2 하드 제약 12종 — 위반 시 해 제외

> 정의·판정식 전문은 `DS-006` §3. 여기서는 최적화 모델에서의 표현만 정리한다.

| ID | 제약 | 근거 | 모델 표현 |
|---|---|---|---|
| HC-01 | 주 소정+연장 ≤ 52시간 | 근기법 §50·§53 | `Σ_{t∈week}(h+ot) ≤ 52` |
| HC-02 | 1일 근로 ≤ 12시간 | 근기법 §53 | `h[e][t]+ot[e][t] ≤ 12` |
| HC-03 | 근무 간 휴식 ≥ 11시간 | 인사규정 §22 | 금지 조합 테이블 (예: `WT-03`→`WT-01` 불가) |
| HC-04 | 휴게 4h/30분·8h/60분 | 근기법 §54 | 근무유형 정의에 내재 |
| HC-05 | 주 1회 이상 유급휴일 | 근기법 §55 | `Σ_{t∈week} x[e][t][WT-00] ≥ 1` |
| HC-06 | 연속 근무일 ≤ 6일 | 인사규정 §19 | 슬라이딩 윈도우 7일 내 휴무 ≥ 1 |

### 4.3 소프트 제약 — 목적함수

```
minimize   Z = Σ wᵢ · normalize( penaltyᵢ )
```

| ID | 항목 | 가중치 | 방향 | 산식 |
|---|---|---|---|---|
| SC-01 | **야간·휴일 배정 형평성** | **0.30** | 최소화 | 직전 3개월 누적 야간·휴일 배정 횟수의 **지니계수** |
| SC-02 | 필요인력 대비 과부족 | 0.25 | 최소화 | `Σ|cov − req|` (부족은 2배 가중) |
| SC-03 | 개인 희망 근무/비번 반영 | 0.18 | 최대화 | 희망 일치 건수 / 희망 신청 건수 |
| SC-04 | 근무유형 연속성 | 0.12 | 최대화 | 연속 3일 이상 동일 유형 비율 |
| SC-05 | 연장근로 총량(인건비) | 0.09 | 최소화 | `Σ ot × 가산율` |
| SC-06 | 숙련–신입 페어링 | 0.06 | 최대화 | 슬롯별 숙련도 표준편차의 역수 |
| | **합계** | **1.00** | | |

**SC-01을 최상위에 둔 이유** — 2026-09-16 현업협의(MT-2026-031) 결정사항 D-03.
현업 요구는 "야간·주말이 특정 인원에게 몰리지 않을 것"이었고, 이를 **가중치 1위(0.30)** 로 반영했다.
초안은 필요인력 충족(SC-02)이 0.43으로 1위였으나, 형평성 0.12 → 0.30, 충족률 0.43 → 0.25로 재조정했다.

### 4.4 형평성 산정 방식

```
누적 대상 기간   직전 3개월 (롤링)
집계 단위       사원별 야간 배정 횟수, 휴일 배정 횟수 (각각 별도 집계)
지표            지니계수 — 0에 가까울수록 균등
목표            부문 내 지니계수 ≤ 0.15
개인 상한       월 야간 배정 ≤ 8회  (HC 신규 제약 승격 검토 — §9.3)
```

> **미확정** — 누적 대상 기간(3개월 / 6개월 / 연간)이 고객 인사팀 확정 대기 중이다.
> 기간이 길수록 장기 형평성은 좋아지나 단기 편중을 허용한다. (§10 P-02)

## 6. 배정 근거 생성 (⑤)

배정 1건마다 아래 3종 근거를 생성해 점포장 화면과 사원 모바일에 노출한다.
**현업 협의 결정사항**(MT-2026-031 D-02)이므로 선택 사항이 아니다.

| 근거 유형 | 내용 | 산출 방법 | 표시 예시 |
|---|---|---|---|
| 소요 근거 | 왜 이 시간대에 인원이 필요한가 | 기준정보 조회 결과 | "토요일 14–16시 계산 부문 기준 인원 6명 (점포운영팀 확정, 2026-08-21)" |
| 제약 근거 | 왜 이 사람이 배정되었는가 | 활성 하드 제약 + 후보 배제 사유 | "정육 자격 보유 4명 중 HC-03(11시간 휴식) 충족자 2명" |
| 형평성 근거 | 배정이 편중되지 않았는가 | SC-01 개인별 위치 | "직전 3개월 야간 배정 3회 · 부문 평균 3.2회 · 지니 0.11" |

### 6.1 사원 이의제기

```
배정 확인(모바일) → 이의 신청 → 점포장 검토(24h 내) → 조정 또는 사유 회신
                                       └─▶ 조정 시 영향 범위만 재최적화
```

이의 사유는 코드로 수집해 SC-03(희망 반영) 개선에 활용한다. **학습 데이터로 쓰지 않는다.**

### 8.2 입력 품질 게이트

배치 시작 전 검증하고, 실패 시 **직전 확정 스케줄을 유지**한 채 알림한다.

|---|---|
| 필요인원 기준 등록률 | ≥ 95% 슬롯 |
| 인사 마스터 동기화 지연 | ≤ 24시간 |
| 근태 신청 확정률 (편성 2주 전) | ≥ 90% |
| 근무유형 마스터 무결성 | 14종 전건 유효 |

### 8.3 실패 시 폴백

| 상황 | 동작 |
|---|---|
| 실행 가능해 없음 | 부분해를 내지 않는다. **위반 제약 ID와 해당 사원·일자를 지목**해 점포장에게 전달 |

### 9.3 미달 원인 분석

| 미달 지표 | 원인 | 귀속 | 대응 | 대응 후 예상 |
|---|---|---|---|---|
| 최적화 소요 412초 | 예외 5종을 하드 제약으로 못 넣고 후처리 필터로 우회 | **`DS-014` 예외 5종 미확정** (ISS-014) | 예외 5종 확정 → 하드 제약 편입 + 웜스타트 | 130~160초 |
| 충족률 91.2% | 4개점 중 2개점이 필요인원 임시값 사용 | **`DS-016` 기준정보 미확보** (ISS-018) | 27개점 기준정보 확정 | 94~96% |

> **4개 미달 중 3개가 입력 조건, 1개가 엔진 설계 문제다.**
> 입력 조건 3건은 알고리즘을 바꿔도 해소되지 않는다.
> 엔진 고유 문제인 형평성은 원인이 명확하다 — 현업이 가장 중요하게 본 항목을 **소프트 제약으로 두었기 때문**이다.
> 가중치를 0.30까지 올려도 다른 항목과 교환 관계에 있는 한 편중은 남는다. **상한을 하드 제약으로 거는 것이 정답**이다.
