# 데이터 연계 규칙 (v1.0)

> **한 줄 요약** — WBS는 "무엇이 얼마나 늦었는가"만 안다.
> "왜 늦었는가"는 회의록·액션아이템·산출물·이슈·CR에 흩어져 있다.
> 이 문서는 그 다섯 문서를 **WBS_ID 하나로 묶는 규칙**이다.

---

## 1. 조인 모델

```
                        ┌──────────────────────┐
                        │        WBS           │
                        │  (WBS_ID = PK)       │
                        │  일정 · 진척 · 선행   │
                        └──────────┬───────────┘
                                   │  WBS_ID  (전 문서 공통 외래키)
      ┌────────────┬───────────────┼───────────────┬────────────┐
      │            │               │               │            │
┌─────┴─────┐ ┌────┴─────┐  ┌──────┴──────┐ ┌──────┴─────┐ ┌────┴─────┐
│  회의록    │ │액션아이템 │  │ 설계산출물   │ │ 이슈/리스크 │ │  CR대장  │
│ 결정/미결  │→│ 이행 추적 │  │ 검토·승인상태│ │ 외부의존 Y/N│ │ 범위변경 │
└───────────┘ └──────────┘  └─────────────┘ └────────────┘ └──────────┘
   RC-02         RC-05          RC-04/08        RC-07/10       RC-01
```

**2차 조인 키** — 근거의 인과를 잇는 보조 키

| 키 | 방향 | 용도 |
|---|---|---|
| `회의ID` | 회의록 → 액션아이템(`출처회의ID`) | "이 결정이 어떤 실행으로 이어졌는가" |
| `산출물ID` | WBS(`산출물ID`) ↔ 산출물목록 | "이 TASK가 만드는 문서" |
| `후행착수TASK` | 산출물 → WBS | "이 문서가 승인돼야 시작할 수 있는 TASK" |
| `선행TASK` | WBS → WBS | 연쇄 지연 전파 경로 |

## 2. 필수 입력 규칙 (Non-Null Constraint)

| 문서 | 반드시 채워야 하는 컬럼 | 비면 잃는 것 |
|---|---|---|
| WBS | `WBS_ID`, `계획종료일`, `진척률`, (지연 시)`지연사유코드` | 지연 판정 자체가 불가 |
| 회의록 | `연관WBS_ID`, 미결사항의 `결정필요일`·`결정권자` | RC-02 탐지 불가 |
| 액션아이템 | `출처회의ID`, `연관WBS_ID`, `완료기한`, `지연영향도` | 근거 체인 단절 |
| 산출물 | `계획완료일`, `검토상태`, `후행착수TASK` | RC-04 인과 확인 불가 |
| 이슈 | `연관WBS_ID`, `외부의존`, `조치기한` | RC-07 탐지 불가 |
| CR | `연관WBS_ID`, `승인일`, `영향공수`, `재기준선반영` | RC-01 탐지 불가 · SPI 왜곡 |

## 4. 지연 원인 도출 파이프라인

```
[1] 수집      6종 문서 로드 → WBS_ID 정규화(공백·전각 제거, 계층 코드 검증)
   ↓
[2] 무결성    V-01 ~ V-10 점검 → 치명 위반은 분석 제외 + 리포트 상단 경고
   ↓
[3] 지연 식별  기준일 > 계획종료일 AND 진척률 < 100  →  지연 TASK 집합
   ↓
[4] 근거 수집  각 지연 TASK의 WBS_ID로 5개 문서 조인
              + 선행TASK 재귀 탐색(깊이 3)  →  근거 레코드 집합
   ↓
[5] 규칙 평가  R-01 ~ R-10 판정식 실행 → 매칭된 원인코드 + 가중치
   ↓
[6] 원인 확정  점수 = 규칙 가중치 + 신뢰도 가산
              최고점 = 주원인, 0.5 이상 = 부원인
   ↓
[7] 처방 생성  RC 코드 → 표준 대응 매핑 + 근거에서 추출한 구체값 치환
              (담당자, 결정권자, 대외기관, 미조치 건수 등)
   ↓
[8] 만회 계산  조치별 회복일수 → 크리티컬패스 재계산 → 오픈일 시뮬레이션
```

### 신뢰도(Confidence) 산정

```
confidence = min(1.0, 규칙가중치 + Σ(근거가산))

근거가산  회의록 미결 1건        +0.10
         액션아이템 기한초과 1건 +0.10
         이슈 미종결 1건         +0.15
         CR 미반영 1건           +0.15
         산출물 미승인 1건       +0.10

표시   0.85 이상 = 높음 / 0.60~0.84 = 보통 / 0.60 미만 = 낮음(사람 확인 필요)
```

## 5. 주원인이 여러 개일 때

한 TASK에 규칙이 2개 이상 매칭되는 것이 정상입니다. 처리 원칙:

1. **점수 최고값 = 주원인.** 리포트와 Pareto 집계는 주원인 기준으로만 계산합니다. (지연일수 이중계상 방지)
2. **0.5 이상 = 부원인.** 화면에는 표시하되 집계에서 제외합니다.
3. **RC-03(연쇄)이 주원인이면 근본 원인까지 추적합니다.** 선행 TASK의 주원인을 함께 표기합니다.
   예: `5.2.1 → RC-03(선행 4.3.2 미완) → 근본원인 RC-02(의사결정 지연)`
4. **동점이면** 대분류 우선순위로 결정: 외부 > 범위 > 관리 > 일정 > 품질 > 자원 > 기술 > 환경

## 6. 리포트 산출 항목

| 구분 | 항목 | 산식 |
|---|---|---|
| 진척 | 전체 진척률 | Σ(단계 가중치 × 단계 진척률) |
| | SPI | EV / PV |
| | CPI | EV / AC |
| 지연 | 지연 TASK | 기준일 > 계획종료일 AND 진척률 < 100 |
| | 지연일수 | 기준일 − 계획종료일 |
| | 진척 부진 | 계획진척률 − 실적진척률 ≥ 20%p |
| 원인 | 원인별 지연일수 | Σ(주원인이 해당 RC인 TASK의 지연일수) |
| | Pareto 기여도 | 원인별 지연일수 / 전체 지연일수 |
| 만회 | 회복 가능일수 | Σ(조치별 회복일수), 중복 제거 |
| | 예상 오픈일 | 크리티컬패스 재계산 결과 |

## 7. 도입 시 최소 요건

이 분석이 동작하기 위해 조직이 실제로 바꿔야 하는 것은 **4가지뿐**입니다.

1. 회의록 양식에 **연관 WBS_ID** 칸을 추가한다.
2. 미결사항에 **결정필요일·결정권자**를 적는다.
3. 액션아이템에 **연관 WBS_ID**를 적는다.
4. 지연 TASK에 **RC 코드**를 고른다. (10개 중 택1)

나머지(이슈·CR·산출물 대장)는 대부분의 SI 프로젝트가 이미 관리하고 있는 문서입니다.
새 도구를 도입하는 것이 아니라, **이미 쓰는 문서에 조인 키를 넣는 것**이 전부입니다.
